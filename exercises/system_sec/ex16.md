**Is it correct and true?**

**Is it good or bad advice? Why?**
- Good advice = reduces attack surface, follows least privilege, adds a layer of defence
- Bad advice = vague ("use good passwords"), outdated, or introduces new complexity without clear benefit

**Example of a strong answer:**

> **Point: "Disable unused services"**

> It's good advice because it directly reduces the attack surface. The only cost is the time to identify and stop the services — which is low compared to the risk.

# Exercise 16.2 — AI-Generated Hardening List

**Step 1 — Ask an AI** (ChatGPT, Claude, etc.) this prompt:

> "Give me a Linux server hardening checklist with at least 10 points. For each point include a brief explanation of why it matters."



## Evaluate points 1, 2, 3, and 7

For each, answer:

| Question | What to write |
|----------|--------------|
| Is it good/bad advice? | Does it reduce attack surface, enforce least privilege, or add a detection layer? |
| Is it practical? | Can you actually do it in 5–30 minutes on your Ubuntu server? Or does it require enterprise tooling? |
| How much effort? | Low (one command), Medium (config file edit), High (major architecture change) |

**Example structure:**

> **Point 1 — "Keep the system updated" (`apt update && apt upgrade`)**
> Good advice — patching is the #1 technical defence (Session 4). Practical — one command, low effort. Every hardening list has this because it addresses the second most common attack vector directly.

> **Point 3 — "Configure a firewall"**
> Good advice — covered in Session 11. Practical with iptables. Medium effort to set up properly (rules, persistence). Risk without it: all ports open by default.

> **Point 7 — [whatever AI generates]**
> Evaluate honestly — is it vague? Specific? Verifiable?



## Is the AI list better than the expert lists?

Use this reasoning for your answer:

- **AI strengths:** Comprehensive, structured, includes explanations, adapts to your specific question, up-to-date knowledge, explains the WHY (sometimes better than "expert" lists)
- **AI weaknesses:** Can hallucinate commands, may give generic advice not suited to your specific OS version, no accountability for errors, can't know your specific environment
- **Expert lists:** Written by practitioners with real experience, but vary wildly in quality, often outdated, sometimes no explanation ("just do this")
- **Conclusion:** Neither is good enough alone. You use both as input, then verify each point yourself against your actual environment.



# Exercise 16.3 — Company Hardening List Discussion

These are the discussion questions Kristoffer wants you to think through. Here are the key points to hit for each:



**Should your company have a server hardening list? Why?**
Yes — without a list, hardening depends on whoever sets up the server remembering everything. People make mistakes. A checklist ensures consistency across all servers and across all engineers. It also satisfies compliance requirements (ISO 27001, NIS2).



**What is similar across the lists you've seen?**
Almost every list includes: update software, disable root SSH, use a firewall, remove unnecessary services, use strong authentication. These are the universal baseline — they appear because they address the most common attack vectors.



**Why are there differences between lists?**
Different authors, different audiences (IoT vs web server vs enterprise), different OS versions, different threat models. A list for a startup web server is different from one for a hospital's database server. There is no single correct answer.



**Can you use an external list directly for your company? Can you use an AI list directly?**
No — not directly. Every point needs to be:
1. Verified (is this advice actually correct for our OS version?)
2. Tested (does applying it break anything in our environment?)
3. Adapted (does our software require something that this point would block?)

An AI or expert list is a starting point, not a finished product.



**How should you select content for your company list?**
Start with a baseline (pick one reputable list), cross-reference with others, remove points that don't apply to your environment, add company-specific requirements, test each point on a staging server before production, document the WHY for each point so future engineers understand the reasoning.



**Should all your servers have the same hardening list?**
No — a web server, a database server, and a mail server have different attack surfaces and different required services. The baseline is the same, but server-role-specific rules will differ. Example: a web server needs port 443 open; a database server should have no public ports at all.



**How should you maintain the list?**
Review it regularly — at minimum annually, and also when:
- A major vulnerability is discovered (e.g. Log4Shell)
- You deploy a new type of server
- Software or OS versions change
- After a security incident

Treat it like code — version control it, review changes, document who changed what and why.



**What can you learn from this exercise?**
That security is not a product you buy — it's a process you maintain. No list is complete or permanent. The value is in understanding the WHY behind each point, so you can adapt when something changes.



**Will AI replace you when you have work experience?**
This is Kristoffer's actual exam question in disguise. The answer he's looking for:
> AI can generate lists and explain concepts. But AI cannot know your specific environment, test whether a hardening step breaks your application, take responsibility for a security incident, or make judgment calls under pressure. A security professional with real experience — who understands the WHY, not just the HOW — is not replaceable by AI. You become harder to replace the more you understand the reasoning behind the tools.
